Overview

The competing-risks path mirrors the survival UX introduced in the refactor: build a task, fit registered engines, obtain tidy predictions/metrics, and visualise or explain with standard verbs. This vignette illustrates the workflow on the classic bone marrow transplant (BMT) dataset.

1. Packages and data

library(ml4time2event)
library(dplyr)
library(ggplot2)

get_bmt_competing_risks_data() returns the prepared dataset that was used in the legacy API. We only need to split the multi-class status into a binary event flag plus a separate cause column.

bmt_raw <- get_bmt_competing_risks_data()

bmt_df <- bmt_raw |>
  mutate(
    cause = if_else(status == 0L, NA_integer_, status),
    status = if_else(status == 0L, 0L, 1L)
  )

2. Build a competing-risk task

cr_task <- ml4t2e_task_cr(
  data = bmt_train,
  time = "ftime",
  status = "status",
  cause = "cause",
  features = c("sex", "d", "phase", "age", "source"),
  time_units = "years"
)

The task stores the time range, the cause mapping, and the feature set that downstream engines rely upon.

6. Pipelines with preprocessing and resampling

Pipelines provide the same interface for competing risks. The example below fits two engines with a simple recipe (median imputation + dummy encoding) and three-fold cross-validation.

library(recipes)
library(rsample)

cr_pipeline <- ml4t2e_pipeline(
  outcome = list(
    type = "competing_risk",
    time = "ftime",
    status = "status",
    cause = "cause"
  ),
  models = c("cox", "fine_gray", "cr_random_forest"),
  ensemble = "auto",
  recipe = recipe(status ~ ., data = bmt_train) |>
    step_impute_median(all_numeric_predictors()) |>
    step_dummy(all_nominal_predictors()),
  resampling = vfold_cv(bmt_train, v = 3)
)

cr_pipeline$fit(bmt_train)

Summary

The competing-risks UX now matches the survival path: define a task, fit registered engines, obtain tidy predictions/metrics, and layer in preprocessing/resampling through pipelines when needed. Ensembles are controlled through the same ensemble argument, and the outputs stay consistent across survival and competing-risk workflows.

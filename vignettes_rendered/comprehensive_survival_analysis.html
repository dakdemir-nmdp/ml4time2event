Overview

The refactored ml4time2event package centres on three tidy verbs:

  1. create a task with ml4t2e_task_surv() or ml4t2e_task_cr()
  2. fit engines through ml4t2e_fit()
  3. work with tidy tibbles returned from predict(), ml4t2e_evaluate(), and autoplot().

This vignette walks through an end-to-end survival workflow that showcases the new API. We will:

  • explore the built-in lung cancer dataset
  • train a collection of survival engines (with optional ensembling)
  • score a hold-out set and compare metrics
  • visualise survival curves and permutation-based feature importance
  • wrap everything into a reusable pipeline (recipes + resampling)

2. Build a survival task

Tasks capture the outcome columns, the feature set, and lightweight metadata.

feature_cols <- c(
  "age", "sex", "ph.ecog", "ph.karno", "pat.karno",
  "meal.cal", "wt.loss"
)

surv_task <- ml4t2e_task_surv(
  data = lung_train,
  time = "time",
  event = "status",
  features = feature_cols,
  id = "id",
  time_units = "days"
)

3. Fit multiple engines (with optional ensemble)

ml4t2e_fit() pulls constructor definitions from the internal registry. The controls list lets us share hyperparameters (e.g. the common prediction grid).

surv_fit <- ml4t2e_fit(
  task = surv_task,
  models = c("cox", "random_forest", "gbm", "gam", "xgboost", "shallownn", "ttah"),
  ensemble = "auto",
  controls = list(times = seq(0, 1000, length.out = 75))
)

# 6. Conformal Prediction Bands

We can also generate calibrated confidence bands for the survival curves using conformal prediction. This requires fitting the model with a calibration split.


``` r
# Fit with conformal calibration (using 20% of data for calibration)
surv_fit_conformal <- ml4t2e_fit(
  task = surv_task,
  models = c("cox", "random_forest"),
  ensemble = "auto",
  controls = list(times = seq(0, 1000, length.out = 75)),
  conformal_calibration = 0.2
)

# Predict with 90% confidence bands (alpha = 0.1)
preds_conformal <- predict(
  surv_fit_conformal,
  newdata = lung_test[1:3, ], # Predict for first 3 patients
  times = seq(0, 1000, length.out = 75),
  type = "survival",
  include = "ensemble",
  conformal_alpha = 0.1
)

# Visualize bands for the first patient
library(ggplot2)
preds_p1 <- preds_conformal %>% filter(id == lung_test$id[1])

ggplot(preds_p1, aes(x = time, y = surv)) +
  geom_line(color = "blue") +
  geom_ribbon(aes(ymin = lower, ymax = upper), alpha = 0.2, fill = "blue") +
  labs(
    title = "Survival Curve with 90% Conformal Confidence Bands",
    y = "Survival Probability", x = "Time"
  ) +
  theme_minimal()

8. Pipelines with recipes and resampling

For workflows that require preprocessing and resampling, wrap everything in a T2EPipeline. Recipes are optional, but when supplied they are baked automatically during prediction/evaluation.

library(recipes)
library(rsample)

surv_pipeline <- ml4t2e_pipeline(
  outcome = list(type = "survival", time = "time", event = "status"),
  models = c("cox", "random_forest", "gbm", "xgboost"),
  ensemble = "auto",
  recipe = recipe(~., data = lung_train) |>
    step_impute_median(all_numeric_predictors()) |>
    step_dummy(all_nominal_predictors()),
  resampling = vfold_cv(lung_train, v = 3)
)

surv_pipeline$fit(lung_train)

Conclusion

The new object-oriented surface keeps common analyses compact:

  1. declare a task,
  2. fit one or more registry-backed engines (optionally with ensembling),
  3. reuse the same tidy outputs across prediction, evaluation, visualisation, and explainability.

The pipeline helpers layer on recipes/resampling without sacrificing the simplicity of the core verbs.
